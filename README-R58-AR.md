## 2) الجذر في الكود (سطر واحد يفسر كل شيء)

```python
# app/backtest/engine1.py — قبل R58:
risk_amount = account_balance * config.position_size_percent   # السطر 540
sl_frac = float(_sl_cfg) / 100.0                                # SL يقسم على 100!
tp_frac = float(_tp_cfg) / 100.0                                # TP يقسم على 100!
```

**التناقض القاتل**: `stop_loss_percent` و`take_profit_percent` يُفسَّران كنسبة
مئوية (49 ⇒ ÷100)، بينما `position_size_percent` يُضرب **ككسر مباشرة**.
الواجهة ترسل الجميع بصيغة واحدة (1 بمعنى 1%، و49 بمعنى 49%) — ففُهم الستوب
والتيك صح، وفُهم الحجم `1.0` = **100% من الرصيد**. ولهذا أيضًا كان حد
القبول في المخطط `le=1.0` — أي أن الواجهة لا تستطيع أصلًا إرسال «100%»!

ثم تنهار البقية تباعًا: لا فحص «هل الرصيد ≤ 0؟» قبل فتح مركز ⇒ أحجام سالبة ⇒
انعكاس PnL$ ⇒ استمرار بعد الإفلاس ⇒ أرقام مستحيلة.

## 3) الإصلاح (R58 — 3 جدران + توحيد الدلالة)

1. **توحيد دلالة الحجم** (`_resolve_risk_fraction`): في وضع `percentage`
   القيمة **نسبة مئوية حقيقية** (1 = 1%، 100 = كامل الرصيد) — نفس منطق
   SL/TP. الوضع `fixed`/الافتراضي يبقى كسرًا تاريخيًا (1.0 = 100%) **بت-بت**
   فلا يتغير أي سلوك قديم غير واجهتك. القيمة تُقصّ إلى [0, 1] نهائيًا.
2. **حاجز الإفلاس (Liquidation)**: أول شمعة يُكتشف فيها رصيد ≤ 0 ⇒ تصفية
   كاملة لكل المراكز المفتوحة («Liquidation (Account Blown)») ثم **وقف
   المحاكاة** — لا صفقة تُفتح بعد الإفلاس إطلاقًا، ولا حجم سالب يمكن أن
   يوجد. الرصيد يُثبَّت عند **صفر** (الحساب لا يخسر أكثر من رأس ماله).
3. **جدار نهاية النافذة داخل المحرك** (خط دفاع ثانٍ بعد قصّ R57 في الكاش):
   لا شمعة تُتداول بعد `end_date` مهما تسرب — والإغلاق عند إغلاق آخر شمعة
   داخل النافذة (= القيمة عند نهايتك بالضبط).
4. **أرضية الواقع المالي في الملخص**: منحنى الرصيد يُقطّع عند الصفر ⇒
   `total_pnl_percent ≥ -100%` و`max_drawdown ≤ 100%` دائمًا، مع شفافية
   كاملة في `math_audit`: `account_liquidated` + `liquidation_truncated`
   (المقدار المقطوع) + `risk_echo` الجديد (ما استلمه المحرك وما طبّق فعلاً).

الشارت كان على 5m مستقلًا عن فريم الباك-تست. **المطلوب من وكيل الفرونت إند**
(موثق في INSTALL-R58): مزامنة فريم الشارت مع فريم الباك-تست + عرض عدد
الشموع الحقيقي المستخدم.
