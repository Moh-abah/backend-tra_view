# 🔧 جولة إصلاح بطء وتعليق جلب البيانات — حزمة التحديث (2026-10-28)

## ماذا تُصلح هذه الحزمة؟
النظام كان يهنق ويتجمد عند جلب البيانات من الداشبورد بسبب 3 جذور:
1. جلب 528 طلباً متسلسلاً لسنة الدقيقة → دقائق انتظار
2. كاش Redis يخزن ~100MB JSON بعملية تحجب الخادم كله ثم يفشل → إعادة جلب كامل كل مرة
3. تحويلات CPU ضخمة (دمج 528 إطاراً + JSON 66MB) داخل الـ event loop → تجمد حتى /health

## ملفات هذه الجولة (استبدلها كلها)
- `app/providers/binance_provider.py` — جلب متوازٍ (8 دفعات) + كاش قرص Parquet + retry/backoff
- `app/services/data_service.py` — سقف كاش Redis (30k صف) + تحويلات في threads
- `app/routers/market_data.py` — بناء استجابة 66MB في thread + إرجاع Response جاهز
- `app/config.py` — إعداد `DATA_CACHE_DIR` (افتراضي: data/history)
- `docker-compose.yml` — volume `./data/history:/app/data/history` لخدمتي backend وcelery
- `reports/REPORT_DATABASE_API.md` + `reports/FINAL_REPORT_AR.md` — توثيق كامل (§5 و§8)

## خطوات التطبيق
1. خذ نسخة احتياطية وأوقف الخدمة
2. انسخ محتوى هذا الـ ZIP فوق جذر مشروع trading-backend (نفس المسارات — وافق على الاستبدال)
3. **مهم:** أنشئ مجلد `data/history` بجانب docker-compose.yml على السيرفر (المجلد نفسه يُنشأ تلقائياً داخل الحاوية، لكن الـ volume يحتاجه موجوداً على المضيف — Docker ينشئه تلقائياً أيضاً عند أول تشغيل)
4. شغّل: `docker compose up -d --build`
5. بعد أول جلب لأي نافذة ستكون الطلبات التالية فورية تقريباً (الكاش يحدّث الذيل فقط)
