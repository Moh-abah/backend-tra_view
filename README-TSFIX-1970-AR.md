# 🔧 TS-FIX-1970 — إصلاح عطب الطوابع الزمنية 1970 (فريم 15m · المهمة #10000378)

## ما المشكلة؟

التشغيلات الكمومية على فريم 15m كانت تُرجع أحياناً **طوابعاً زمنية مكسورة**:
كل الشموع تحمل `1970-01-01T00:00:00.{N}Z` — 15,313 شمعة تتقاسم **16 طابعاً
فقط** (1000 شمعة لكل قيمة)، ونقاط الصفقات تحمل **فهرس الشمعة** كميكروثانية
(الدخول الأول عند `4956µs` = الشمعة رقم 4956)، و`metadata.start_date = 1970`
و`overlays.time_from/time_to = 0/0`. النتيجة: الشارت يرسم شمعة واحدة.

**العلة متقطعة** — نفس الإعداد: #10000375 و#10000379 سليمتان و#10000376/377/378
مكسورة — لأنها تعتمد على عمر مدخل كاش redis (TTL ساعة).

## السبب الجذري (سلسلة من ثلاث طبقات)

1. **كتابة مسمومة** — `data_service.get_historical_last_version` كان يخزّن
   `df.to_dict('records')` **بعد** `set_index('time')` — و `to_dict` لا يتضمّن
   الفهرس! فيُفقد البعد الزمني كله عند التخزين في redis.
2. **قراءة + مخطط مسموم** — أي تشغيلة تالية خلال ساعة تقرأ سجلات بلا زمن
   ⇦ إطار بفهرس رقمي (0..n) ⇦ `_capture_df_schema` يلتقط مخططاً بلا عمود
   زمن ⇦ إعادة بناء كاش الشموع **تطرد عمود `time` من سجلات جيدة** عبر
   `df[columns]`.
3. **التسميم النهائي** — `engine1._normalize_candle_index` يحوّل الفهرس
   الرقمي عبر `pd.to_datetime(index, utc=True)` الذي يفسّر الأعداد الصحيحة
   كنانو-ثوانٍ منذ الحقبة ⇦ الشمعة رقم i تحصل على `1970-01-01 + i نانوثانية`
   (لهذا تظهر 1000 شمعة لكل ميكروثانية بعد تقريب pydantic للميكروثانية).

المحرك المالي نفسه سليم تماماً (المحاكاة موضعية لا زمنية) — لهذا كانت
المقاييس صحيحة دائماً (+69.34% · 31 صفقة) بينما الطبقة الزمنية مكسورة فقط.
